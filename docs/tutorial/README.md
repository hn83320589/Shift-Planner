# Shift Planner 教學文件

本文件以「客服中心智慧排班系統」這個**完整、可執行、經過驗收**的專案為教材，從程式設計與系統分析的角度，帶你走過一個中型系統從需求到交付的全過程：

> 一間 24 小時營運的客服中心，16 位客服人員，早／晚／夜三班輪值。主管每個月要花兩天用 Excel 排班，還常被指出違反勞基法或分配不公平。他們要一套能自動產生班表、也能讓主管手動微調的系統。

這不是「怎麼用某個框架」的教學，而是「**怎麼想**」的教學：如何把模糊的需求變成精確的規格、如何切分系統、如何把一個困難的組合最佳化問題交給求解器，以及如何證明系統真的做對了。

---

## 學習目標

讀完本文件，你應該能夠：

1. **系統分析**：把自然語言需求拆解成名詞、規則、邊界，並寫成可測試的規格。
2. **領域建模**：分辨實體、值物件與聚合，用型別系統表達業務規則與狀態機。
3. **架構設計**：依「依賴方向」切分專案，說明每個設計決策的取捨。
4. **規則引擎**：用策略模式實作可獨立測試的驗證規則，並正確處理時間區間與跨月邊界。
5. **限制規劃（Constraint Programming）**：把排班問題寫成 CP-SAT 模型，包括變數、線性限制、加權目標函數，以及把 max − min 這類非線性目標線性化。
6. **可解釋性**：在求解器只回答「無解」時，設計能說出「為什麼」的診斷機制。
7. **增量重排**：用「凍結 + 基準差異」實作最小變動的重新排程。
8. **測試策略**：TDD、邊界值分析、整合測試、端對端測試，以及處理非決定性演算法造成的不穩定測試。

## 如何搭配程式碼閱讀

```bash
git clone https://github.com/hn83320589/Shift-Planner.git
cd Shift-Planner
dotnet test                                   # 116 個測試
dotnet run --project src/ShiftPlanner.Web     # 開啟終端機顯示的網址
```

各章引用程式碼時都會標出檔案路徑，例如 `src/ShiftPlanner.Core/Validation/RestPeriodRule.cs`。建議一邊讀一邊打開對應檔案，並實際執行相關測試，例如：

```bash
dotnet test --filter RestPeriodRuleTests
```

每章最後都有**練習題**。標示 ★ 的題目需要修改程式並補上測試，適合當作作業。
