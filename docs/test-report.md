### D-4　跨月重排造成已發布的下個月違規（高）

- **重現步驟**
  1. 發布 11 月和 12 月。
  2. 對 11 月建立臨時重排：員工 #2，11/28–11/30 請假。
  3. 套用後查看 12 月。
- **實際結果**：12 月出現 4 個硬性違規，例如「鄭惠如 11/30 夜班 → 12/1 早班 只休息 0 小時」。
- **原因**：重排模型和套用時的驗證，都只把**前一個月**當作固定上下文。已發布的**下一個月**沒有被當作限制，月底新排的班可能和下個月月初衝突，跨月週的工時和休息日也可能超出限制。
- **修正建議**：
  - `GenerationRequest` 加入「範圍之後的固定班次」，模型在休息、每週、連續天數的限制中代入這些常數。
  - 套用重排前，若下個月已發布，同時驗證下個月；有違規就拒絕套用。
  - 補上對應的單元測試與整合測試。

### D-2　CSV 分數欄在 Excel 中變成日期（中）

- **重現步驟**：匯出 11 月月報 CSV，用 Excel 開啟。
- **實際結果**：`2/2` 顯示為「2026年2月2日」、`1/2` 顯示為「2026年1月2日」。
- **原因**：Excel 會把 `數字/數字` 的字串自動辨識成日期。
- **修正建議**：把兩個分數欄拆成四個純數字欄（強烈偏好滿足數、強烈偏好登記數、一般偏好滿足數、一般偏好登記數）。畫面共用同一組欄位，兩邊仍然一致。補上「CSV 中沒有 `n/m` 格式欄位」的測試，並以 Excel 重新驗證。

### D-1　計時沒有透過 TimeProvider（低）

- **位置**：`src/ShiftPlanner.Scheduling/ShiftScheduleGenerator.cs:17`，`Stopwatch.StartNew()`。
- **影響**：只用來回報求解耗時，不影響排班結果；但不符合「時間相關邏輯一律透過 TimeProvider 注入」。
- **修正建議**：產生器注入 `TimeProvider`，改用 `GetTimestamp()` / `GetElapsedTime()`，並以 `FakeTimeProvider` 測試。

另外，CP-SAT 求解器內部的時間上限（`max_time_in_seconds`）由原生程式庫自行計時，無法經由 .NET 的 `TimeProvider` 控制。這屬於第三方元件的限制，建議在 README 中說明。

### D-3　首頁多餘字元（低）
