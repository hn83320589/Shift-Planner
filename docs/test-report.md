## 2. 測試範圍與方法

| 層級 | 範圍 | 工具 |
|---|---|---|
| 單元測試 | Validator 7 條規則（含跨月雙向）、人力缺口、國定假日、Schedule 狀態機、月報、CSV、ICS、CP-SAT 產生器、無解診斷、臨時重排、跨月、計時 | xUnit |
| 整合測試 | API、資料庫、發布鎖定與發布順序、臨時重排（含跨月）、匯出 | xUnit + `WebApplicationFactory`、`FakeTimeProvider`、每個測試獨立的 SQLite |
| 跨平台 | 在 Ubuntu 與 Windows 上建置並執行全部測試，各 3 次 | GitHub Actions |
| 系統測試（API） | 從全新 clone 以 `dotnet run` 啟動，對真實 HTTP API 與 SQLite 逐項驗證驗收標準 | Python 腳本 |
| 系統測試（UI） | 實際操作 Blazor 頁面 | Playwright（Chromium） |
| 相容性 | ICS 用第三方 RFC 5545 解析器解析，並由使用者實際匯入 Google 日曆；CSV 用 Microsoft Excel 實際開啟，逐格比對 | `icalendar` 7.3.0、Google 日曆（人工）、Excel for Mac（AppleScript） |
| 穩定性 | 同一份資料連續產生 5 次；Scheduling、Web 測試在本機各連續跑 5 次；CI 重跑 3 次 | — |
| 靜態檢查 | 時間相關邏輯是否全部透過 `TimeProvider` | grep |
| 探索性測試 | 錯誤輸入、發布順序、12 月已發布後重排 11 月底 | Python 腳本 |

> 端對端測試是在 `12131e5` 執行的。之後的產品程式碼只改了一行訊息排版（D-5，`FeasibilityPrecheck.cs`），而且有自動化測試涵蓋；其餘變更都在測試程式，因此端對端結果適用於受測版本。

## 10. 已知限制（不屬於缺陷，已在 README 說明）

- 重排以最少更動為優先，夜班差距只是軟性目標；重排後月報上的夜班差距可能超過 2。
- 下個月尚未發布時，跨月的週只檢查已知的天數；下個月產生與發布時，會以本月為上下文完整檢查。
- 只有已發布的月份會當作上下文；上個月還是草稿時可以先產生本月草稿，但不能發布。
- 休息日以班次開始日判定，沒有區分例假與休息日，也沒有檢查連續 24 小時休息。
